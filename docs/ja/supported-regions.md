# 対応リージョン

[English](../en/supported-regions.md)

## 概要

Amazon FSx for NetApp ONTAP（FSx for ONTAP）と S3 Access Points はほとんどの AWS リージョンで利用可能です。
デプロイを計画する際は、FSx for ONTAP と対象の分析プラットフォームが同じリージョンで利用可能であることを確認してください。

## S3 Access Points の利用可否

S3 Access Points は Amazon S3 が利用可能な**すべての AWS リージョン**で利用できます。
S3 はすべての商用 AWS リージョンで利用可能なため、S3 Access Points による追加のリージョン制約はありません。

### FSx for ONTAP 上の S3 Access Points

FSx for ONTAP の S3 Access Points は、FSx for ONTAP が利用可能なすべてのリージョンで利用できます。
S3 Access Point は FSx for ONTAP ファイルシステムと同じリージョンに作成する必要があります。

### AWS ネイティブサービス（Athena, Glue, Redshift Spectrum）

AWS ネイティブ分析サービスは、FSx for ONTAP が利用可能なすべてのリージョンで利用できます。

| Athena | インターネット | はい（パフォーマンスのため） |
| Glue | インターネット | はい |
| Redshift Spectrum | インターネット | はい |
| EMR | VPC | はい |
| Lambda | VPC | はい |

## リージョン選定の考慮事項

### 主要な判断基準

1. **データレジデンシー / コンプライアンス**
   - 規制要件（GDPR, HIPAA, FISC 等）
   - データ主権に関する法律
   - 業界固有のコンプライアンス要件

2. **レイテンシ**
   - エンドユーザーおよびデータ生成元への近接性
   - サービス間通信のレイテンシ
   - FSx for ONTAP と分析プラットフォームは同一リージョンに配置すべき

3. **サービス利用可否**
   - FSx for ONTAP + 対象プラットフォームの両方が利用可能であることを確認
   - リージョン間の機能パリティを確認

4. **コスト**
   - FSx for ONTAP のリージョン別料金差
   - データ転送コスト（クロスリージョンは高額）
   - 分析プラットフォームのリージョン別料金

### ベンダー別の考慮事項

| ベンダー | 主な考慮事項 |
|---------|-------------|
| **Databricks** | ワークスペースと FSx for ONTAP は同一リージョン必須（VPC スコープ AP） |
| **Snowflake** | アカウントリージョンは FSx for ONTAP リージョンと一致させるべき（レイテンシ最適化） |
| **Athena** | 同一リージョン必須、インターネットネットワークオリジン AP が必要 |
| **Glue** | 同一リージョン必須、インターネットネットワークオリジン AP が必要 |
| **EMR** | 同一 VPC またはピアリング VPC、VPC スコープ AP 対応 |

## マルチリージョンアーキテクチャパターン

### パターン 1: SnapMirror によるクロスリージョン DR

```
┌─────────────────────┐         SnapMirror          ┌─────────────────────┐
│  プライマリリージョン │ ──────────────────────────▶ │  DR リージョン       │
│  (ap-northeast-1)   │                             │  (us-west-2)        │
│                     │                             │                     │
│  FSx for ONTAP      │       非同期/同期           │  FSx for ONTAP      │
│  + S3 AP            │       レプリケーション       │  + S3 AP            │
│  + Databricks       │                             │  + Databricks       │
└─────────────────────┘                             └─────────────────────┘
```

**ユースケース:**
- RPO < 15分（非同期）または RPO = 0（同期）のディザスタリカバリ
- セカンダリリージョンでの分析用読み取りレプリカ
- 特定リージョンへのデータコピーを要求する規制対応

### パターン 2: SnapMirror によるデータ配信

```
                    ┌─────────────────────┐
                    │  ソースリージョン    │
                    │  FSx for ONTAP      │
                    │  (データプロデューサー) │
                    └──────────┬──────────┘
                               │ SnapMirror
                    ┌──────────┼──────────┐
                    │          │          │
                    ▼          ▼          ▼
          ┌─────────────┐ ┌─────────┐ ┌─────────────┐
          │ リージョン A │ │リージョンB│ │ リージョン C │
          │ Databricks  │ │Snowflake│ │ Athena      │
          │ (分析)      │ │(共有)   │ │ (アドホック) │
          └─────────────┘ └─────────┘ └─────────────┘
```

**ユースケース:**
- リージョナルコンシューマーを持つグローバルデータメッシュ
- ローカルデータコピーによるマルチリージョン分析
- コンプライアンス要件に基づくデータ配信

### パターン 3: アクティブ-アクティブ マルチリージョン

```
┌─────────────────────┐                             ┌─────────────────────┐
│  リージョン A       │ ◀── SnapMirror (双方向) ──▶ │  リージョン B       │
│                     │                             │                     │
│  FSx for ONTAP      │                             │  FSx for ONTAP      │
│  Volume: /sales-a/  │                             │  Volume: /sales-b/  │
│  + S3 AP            │                             │  + S3 AP            │
│  + Lakehouse        │                             │  + Lakehouse        │
└─────────────────────┘                             └─────────────────────┘
```

**ユースケース:**
- リージョナルデータパーティショニング（各リージョンが自身のデータを所有）
- リージョン横断のグローバル集計クエリ
- 低レイテンシのローカル書き込みとグローバル読み取り

### SnapMirror 構成の考慮事項

| 要素 | 非同期 SnapMirror | 同期 SnapMirror |
|------|------------------|-----------------|
| RPO | 分単位（スケジュールベース） | ゼロ（同期） |
| 距離 | 任意（クロスリージョン） | 制限あり（同一リージョンまたは近接） |
| パフォーマンス影響 | 最小限 | 中程度（書き込みレイテンシ） |
| ユースケース | DR、データ配信 | データ損失ゼロ要件 |
| コスト | データ転送料金 | より高いスループットが必要 |

## 推奨事項

### 新規デプロイの場合

1. FSx for ONTAP と主要な分析プラットフォームの両方が利用可能なリージョンを選択
2. 最も広いサービス利用可否を持つリージョンを優先（us-east-1, eu-west-1, ap-northeast-1）
3. データレジデンシー要件を最優先し、次にレイテンシとコストを最適化

### マルチリージョンデプロイの場合

1. クロスリージョンデータレプリケーションには SnapMirror を使用
2. 各リージョンに S3 Access Points をデプロイ（リージョンをまたぐことはできない）
3. 同一リージョン内の読み取り専用レプリカには FlexClone を検討
4. リージョン間のデータ転送コストを計画に含める
