## ハードウェア要件

| コンポーネント | 最小 | 推奨 |
|-------------|------|------|
| ボード | Raspberry Pi 4B (4GB) | Raspberry Pi 5 (8GB) |
| ストレージ | 32 GB SD カード | 128 GB USB SSD |
| ネットワーク | イーサネット（工場 LAN） | イーサネット + WiFi（バックアップ） |
| 電源 | USB-C 5V/3A | UPS 付き |

## ONTAP-Edge-to-Cloud-AI との統合

[ONTAP-Edge-to-Cloud-AI](https://github.com/Yoshiki0705/ONTAP-Edge-to-Cloud-AI) が提供:
- Raspberry Pi GPIO でのセンサーシミュレーション
- 品質検査用カメラ統合
- センサーデータの MQTT パブリッシャー

本プロジェクトが提供:
- MQTT → Kafka ブリッジ（ストアアンドフォワード）
- ONTAP へのペイロードアップロード（NFS）
- Instaclustr Kafka 用の設定

### 統合ポイント

```
ONTAP-Edge-to-Cloud-AI              本プロジェクト
(センサー/カメラ → MQTT)   →   (MQTT → SQLite → Kafka + NFS アップロード)
```

### API コントラクト

- MQTT トピック: `sensors/<device_id>/<sensor_type>`
- MQTT ペイロード: `config/environment.yaml` のスキーマに準拠する JSON
- ペイロードファイル: edge-to-cloud-ai が `/tmp/payloads/` に書き込み、本プロジェクトのゲートウェイがアップロード

## 障害モードと復旧

| 障害 | 動作 | 復旧 |
|------|------|------|
| Kafka 到達不能 | イベントが SQLite にキュー（最大 10 GB） | 接続復旧時に自動ドレイン |
| NFS マウント喪失 | ペイロードアップロード失敗 → デッドレター | NFS 再接続; デッドレターファイルをリトライ |
| Raspberry Pi 再起動 | systemd がゲートウェイ再起動; SQLite キュー永続 | 自動 |
| SD カード破損 | サービス起動失敗 | SD 交換; キューデータ損失（受容） |
| 工場停電 | 全サービス停止 | 復電時に自動起動; 一部インフライトデータ損失の可能性 |
